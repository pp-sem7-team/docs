# Gitflow

Данные правила применяются к репозиториям `backend`, `ai-service` и `frontend`.

## 1. Ветки

Используются две основные ветки:
- `main` — стабильная версия;
- `dev` — основная ветка разработки.

Все изменения вносятся только через отдельные ветки и Pull Request. Прямые коммиты в `main` и `dev` запрещены.

Для решения отдельной задачи создаётся рабочая ветка от `dev`.\
Исключение: срочные исправления багов на проде создаются от `main` и вливаются в обе ветки (`main` и `dev`).

**Формат названия ветки:** `тип/номер_задачи-описание`.
- `feat/` — новый функционал;
- `fix/` — исправление багов;
- `docs/` — документация;
- `chore/` — технические изменения.

**Пример:** `feat/42-add-auth`.

## 2. Коммиты
Придерживаемся **Conventional Commits** (`тип(область): описание`):
- `feat` — новый функционал;
- `fix` — исправление ошибки;
- `refactor` — улучшение кода без изменения логики;
- `perf` — изменения для улучшения производительности;
- `docs` — работа с документацией;
- `test` — добавление или изменение тестов;
- `style` — форматирование и изменения, не влияющие на логику;
- `chore` — технические изменения.

**Пример:** `feat(auth): add jwt login`.

## 3. Pull Requests
**Заголовок:** `Краткое описание` (например, `Implement JWT middleware`).

**Описание:**
- **Изменения:** Краткий список изменений.
- **Связанная задача:** Номер задачи из таск-треккера в формате `closes #номер` (например, `closes #42`).
